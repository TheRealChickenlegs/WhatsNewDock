# WhatsNewDock v0.1.0

**Know what changed before you hit update.**

WhatsNewDock is a self-hosted monitor for Docker container updates. It watches
every container across all of your hosts, tells you when a newer image is
available, and shows you **what actually changed** by pulling the release notes
straight from upstream — so updating becomes a decision rather than a leap of
faith.

This is the first release. Everything below is in it.

---

## Highlights

- **See updates, read the changelogs** — release notes from GitHub, GitLab and
  Gitea/Forgejo, with a registry tag fallback when there are none.
- **One-click updates** — pull and recreate through the Docker Engine API, with
  live progress and automatic rollback if the replacement fails to start.
- **Podman / Quadlet aware** — systemd-managed containers are updated by handing
  the recreate to their unit, never behind systemd's back.
- **Every host in one place** — a lightweight agent, a direct Docker API
  endpoint, or a mix of both.
- **Works on your phone** — the whole interface is usable on a phone or tablet.
- **Hardened by default** — non-root distroless image, restricted socket proxy,
  no shell and no `docker` CLI.

## What's in 0.1.0

### Updates you can actually assess

Each container is checked against its upstream releases, and you are told how
many versions behind you are. When you are several versions behind, you get the
changelog for **each version you skipped**, not just the newest one — with a
configurable history (5 releases by default).

Sources are resolved automatically from the image reference and its labels:
GitHub Releases (including `ghcr.io` images and `org.opencontainers.image.source`
labels), GitLab Releases, Gitea/Forgejo releases, and finally Docker Hub or
another registry's tag listing when there are no release notes to fetch.
Private and self-hosted repositories are supported with optional tokens.

### One-click updates

Pressing **Update** pulls the target image and recreates the container from its
existing configuration, entirely through the Docker Engine API — no shell, no
`docker` CLI. Progress is streamed live, and if the replacement fails to start
the original container is restored: its name, and its running state, whatever
its restart policy is.

### Podman and Quadlet

Containers started from a Quadlet unit are recognised by their
`PODMAN_SYSTEMD_UNIT` label and shown with the unit that owns them. They cannot
be recreated the ordinary way — stopping one makes its unit tear it down, so a
rename would hit a container that no longer exists — so the update is handed to
systemd instead: the image is pulled, the container is stopped, and the unit's
`Restart=` policy brings it back on the new tag. Success is only reported once a
container with a new id is observed **running**, so a crash-looping or unchanged
replacement is reported as a failure rather than a silent success.

Two things to know: the unit needs a `Restart=` policy (`on-failure` or
`always`), and the container must be running — a stopped Quadlet container has no
active unit, and the app will tell you to `systemctl start` it first. If you
prefer `podman auto-update` to own the lifecycle, that still works and the app
keeps tracking available updates.

### Every host in one place

Add a host any of three ways:

- **Local** — the Docker socket, reached through a restricted socket proxy
  rather than the raw socket.
- **Agent** — a small container on the remote host that reports in with a
  per-host bearer token. Only outbound connections, so it works across NAT and
  firewalls.
- **Direct endpoint** — point the server at a remote Docker API and skip the
  agent entirely. Off-loopback endpoints must use TLS; certificates are
  referenced as mounted file paths and never stored as PEM in the database.

Containers are grouped by compose project or swarm stack, with Podman pods as a
fallback, and can be browsed as one filtered list or host → stack → container.

### Accounts and sign-in

Local username/password accounts with `admin` and `viewer` roles, and optional
OIDC for any provider (PocketID, Keycloak, Authentik…). Both can be configured
in the UI, and password sign-in can be switched off once OIDC is working.

### On your phone

The interface is designed for phones and tablets as well as desktops: the
sidebar becomes a drawer you can dismiss, the container list becomes cards
instead of a sideways-scrolling table, dialogs become bottom sheets, and
changelog tables scroll inside their own box instead of stretching the page.
The layout is checked automatically at eight widths from 320 px to 1440 px.

### Built to run unattended

- Single Go binary with the UI embedded; **SQLite only** — no external database.
- Runs as a **non-root distroless** container (uid 65532) with no shell.
- The Docker socket is never mounted into the app: the bundled compose runs a
  [socket proxy](https://docs.linuxserver.io/images/docker-socket-proxy/) on an
  internal network and exposes only the API sections the app needs. A
  monitoring-only mode is a two-line change.
- Strict `Content-Security-Policy`, CSRF protection on mutations, bcrypt
  password hashing and signed session cookies.
- CI runs `gosec`, `govulncheck`, `npm audit` and a Trivy scan of every
  published image.

## Quick start

```bash
git clone https://github.com/TheRealChickenlegs/WhatsNewDock.git
cd WhatsNewDock
# set WND_INITIAL_ADMIN_PASSWORD in docker-compose.yml first
docker compose up -d
```

Then open `http://localhost:8080` and sign in. If you do not set a password, one
is generated and printed to the container logs on first run.

Podman users get ready-made Quadlet units for the server, the socket proxy and
the agent in [`deploy/quadlet/`](https://github.com/TheRealChickenlegs/WhatsNewDock/tree/main/deploy/quadlet).

## Container image

Multi-arch (`linux/amd64`, `linux/arm64`), published to GHCR:

```bash
docker pull ghcr.io/therealchickenlegs/whatsnewdock:0.1.0   # or :latest
```

---

## Requirements

- A Docker-compatible Engine API — Docker Engine, or Podman (its
  Docker-compatible service socket works).
- Write access to the data directory for the SQLite database: a named volume, or
  a bind mount owned by uid 65532.

Because this is a 0.1.x release, configuration flags and the on-disk database
schema may still change between minor versions. Back up the data directory
before upgrading.
